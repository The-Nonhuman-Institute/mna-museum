# Resend DNS Setup for mnamuseum.org

## Overview

To send emails from `registry@mnamuseum.org` via Resend, you need to verify the `mnamuseum.org` domain in the Resend dashboard and add the required DNS records to your domain registrar.

**Sending domain:** `mnamuseum.org`
**From address:** `registry@mnamuseum.org`
**API key:** Set as `RESEND_API_KEY` in env files (already configured)

---

## Step 1: Add Domain in Resend Dashboard

1. Go to [resend.com/domains](https://resend.com/domains)
2. Click **Add Domain**
3. Enter `mnamuseum.org`
4. Select your region (US East recommended)
5. Click **Add**

Resend will show you the DNS records to add. They will look similar to the records below.

---

## Step 2: Add DNS Records

Add the following DNS record types to your domain registrar (wherever `mnamuseum.org` DNS is managed):

### SPF Record (TXT)

Authorizes Resend to send email on behalf of your domain.

| Type | Name | Value |
|------|------|-------|
| `TXT` | `mnamuseum.org` (or `@`) | `v=spf1 include:amazonses.com ~all` |

> If you already have an SPF record, add `include:amazonses.com` to the existing record rather than creating a second TXT record at the same name.

### DKIM Records (CNAME)

Cryptographically signs outgoing mail. Resend provides two CNAME records.

| Type | Name | Value |
|------|------|-------|
| `CNAME` | `resend._domainkey.mnamuseum.org` | *(provided by Resend dashboard — unique to your account)* |

> The exact CNAME values are generated by Resend for your specific account. Copy them from the Resend dashboard — do not guess these values.

### DMARC Record (TXT)

Instructs receiving mail servers how to handle failed authentication.

| Type | Name | Value |
|------|------|-------|
| `TXT` | `_dmarc.mnamuseum.org` | `v=DMARC1; p=none; rua=mailto:registry@mnamuseum.org` |

> Start with `p=none` (monitoring mode) to ensure deliverability before moving to `p=quarantine` or `p=reject`. Upgrade once you confirm mail is flowing correctly.

### MX Records (for receiving at registry@mnamuseum.org)

If you want to **receive** replies to `registry@mnamuseum.org`, you need MX records pointing to your email provider. If `mnamuseum.org` already has MX records configured for another provider (e.g., Google Workspace, Fastmail), do not change them — Resend only needs to send, not receive.

If you have no MX records and want replies to reach an inbox, add MX records for your preferred email provider, or forward `registry@mnamuseum.org` to `jballard0726@gmail.com`.

## Step 3: Verify in Resend Dashboard

1. After adding the DNS records, return to [resend.com/domains](https://resend.com/domains)
2. Click **Verify** next to `mnamuseum.org`
3. DNS propagation can take up to 48 hours, though it typically resolves within minutes to a few hours
4. Once verified, the domain status will show as **Verified** with a green indicator

## Troubleshooting

**Emails not delivering after domain is verified:**
- Check that the SPF record doesn't have conflicting `+all` or `-all` that would override Resend's authorization
- Verify DKIM CNAMEs resolved correctly: `dig CNAME resend._domainkey.mnamuseum.org`
- Check Resend's **Emails** dashboard for delivery status and bounce/error details

**`From` address rejected:**
- Resend only allows sending from addresses at verified domains. `registry@mnamuseum.org` requires `mnamuseum.org` to be verified.
- If sending from a subdomain (e.g., `noreply@mail.mnamuseum.org`), add and verify that subdomain separately.

**DMARC failures:**
- Start with `p=none` and monitor the `rua` inbox for aggregate reports
- Only tighten policy after confirming all legitimate mail streams are authenticated
